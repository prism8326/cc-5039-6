# 保护强度边界与合规说明

本实验是一个**教学用的软件测试密钥流程**，目的是讲清 EME/CENC 的机制与授权状态机，而不是提供可
上线的内容保护能力。请严格区分它与商业硬件 DRM 的能力差异。

## 本实验实际提供了什么

- 真实的 **CENC-AES-CTR** 加密封装：媒体字节确实被 AES-128 计数器模式加密，密文≠明文，且只有拿到
  匹配 KEY 的 ClearKey CDM 才能解密还原（已通过逐字节解密比对与真实浏览器渲染验证）。
- 标准的 **W3C ClearKey + EME** 交互：`MediaKeys` / `MediaKeySession` / `generateRequest('cenc')`
  / 许可交换 / `keystatuseschange` / MSE 解密播放，全部走浏览器原生接口，没有桩件模拟。
- 可观察、可复现的授权三阶段与多类失败演练，用于教学判断“卡在哪一阶段”。

## 它不具备、也不声称具备的能力

| 维度 | 本实验（ClearKey 软件测试密钥） | 商业硬件 DRM（如 Widevine L1/PlayReady SL3000/FairPlay） |
| --- | --- | --- |
| 密钥存放 | 由浏览器软件 CDM 在普通内存处理，测试 KEY 甚至以文件形式存在本地 | 可信执行环境（TEE）/安全硬件，密钥不出安全域 |
| 抗逆向/抗调试 | 弱；软件环境可被检视，测试密钥仅用于教学 | 强；硬件级隔离、回滚保护、设备证明 |
| 安全级别证明 | 无 robustness 保障，`robustness` 传空串 | 可协商高 robustness 等级并做设备完整性证明 |
| 输出保护 | 不强制 | 可要求 HDCP 等输出链路保护 |
| 许可模型 | 本地静态 JSON、固定测试场景 | 服务端动态授权、租约、吊销、域名/设备绑定等 |
| 适用内容 | 自制、虚构的教学片段 | 受版权保护的真实商业内容 |

结论：**不能把“ClearKey 软件测试密钥能解密播放”等同于“达到了商业硬件 DRM 的保护强度”。** 前者验证
的是协议与加解密链路的正确性，后者还包含密钥保密、抗攻击与设备信任等一整套硬件支撑的安全属性。

## 合规与安全红线

- 仅使用**自制内容**（ffmpeg 合成的 testsrc2/sine）与**本地虚构课程**；不接入任何第三方受版权保护的
  内容。
- 测试 KID/KEY 仅用于本实验，**禁止用于生产环境或真实内容保护**；密钥库文件权限 0600 且不入库。
- 本项目**不实现、不辅助、也不绕过** Widevine / PlayReady / FairPlay 等任何第三方内容保护体系；
  ClearKey 是 W3C 公开规范定义、浏览器原生提供的测试密钥系统，与上述商业体系相互独立。
- 普通日志、状态接口、界面事件日志均**不输出 KEY 明文**；KID 仅脱敏展示，许可响应显式标注未记录
  密钥材料。
- 许可服务对未登记 KID 一律 404 拒绝，不存在“万能密钥”或绕过路径。

## 教学结论应如何表述

正确表述：“在本地自制内容上，使用浏览器原生 ClearKey CDM，完整跑通了 CENC 加密 → EME 许可 →
密钥 usable → 真实解密渲染的链路，并能区分各阶段失败。”

不应表述：“实现了与商业 DRM 同等强度的保护”或“能够破解/兼容 Widevine、PlayReady、FairPlay”。
